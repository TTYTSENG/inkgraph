# 第二階段：討論、概念與跨專案連結

完成日期：2026-10-23。這份文件記錄本機實作與驗證結果；尚未建立新的 GitHub 發行版本。

## 建議操作順序

1. 在「來源文獻庫」保存原檔或已匯入的 Gemini／NotebookLM 材料。
2. 從來源建立討論，或在「討論與訊息」新增討論。逐則新增訊息，明確指定提問者、AI、研究者或未知角色。
3. 使用「整理成筆記」，輸入自己的理解。系統另外保存討論素材及「衍生自」關係；討論素材會標明待核對，不當成原始文獻證據。
4. 在筆記右側開啟原始依據，並排閱讀原文。將摘錄加入筆記後，保留加入當時的原文、釋義、加註及來源版本。
5. 建立概念頁，將相關筆記、摘錄、討論或字彙條目連到概念。字彙辭典繼續保存個別定義與出處。

匯入已有對話全文時，會保存成一則「未知角色」訊息，不自動猜測發話者；原始來源仍保留。訊息顯示的建立時間是本機保存時間。

## 連結與專案的差別

「建立物件連結」可選引用、討論、關於、定義、衍生自、支持、反駁或相關，並記錄原因與兩端位置。支持／反駁需要填寫理由。兩端頁面都能看到關係並相互跳轉；改名沿用相同 ID。

關係可選「全資料庫」或特定專案。專案範圍只顯示適用的關係；切到全部專案可查閱跨專案脈絡。從連結開啟其他專案物件時，介面會提示目前專案不包含該物件，不會自動將它加入專案。

「專案連結」將同一物件加入多個專案；修改內容會在所有所屬專案顯示。來源、筆記、字彙、討論及概念可重用，訊息沿用其討論的專案範圍。若 A、B 專案對同一來源有不同理解，應共用來源，另外建立各自的筆記，再用關係連結。

## 匯出與刪除

- Markdown／HTML 保留摘錄內容、出處及關係對照。單筆討論匯出包含其訊息；單筆概念匯出保留關係端點名稱與 ID，不自動帶出其他筆記全文。
- 專案匯出會補入所需的原始來源；跨專案關係可保留外部端點資訊，不自動匯出其他專案的全部評論。
- 討論整理的筆記會保存整理時的素材。原討論後續更新不覆寫既有筆記，關係保留引用版本供核對。
- ZIP 備份格式為版本 3；還原仍接受版本 1、2、3。備份包含原始附件；一般報告匯出不等同完整備份。
- 刪除討論會一併刪除所屬訊息及相關連結，確認畫面會顯示影響。刪除概念或連結不會刪除相連的其他筆記。
- 刪除來源會解除討論的來源參照；已整理的討論文字及筆記摘錄快照仍保留。快照缺少原始物件時會顯示核對提醒。
