# v0.1.0 驗證紀錄

日期：2026-10-12（Asia/Taipei）

環境：Windows、Node.js 24.19.0、本機瀏覽器 Chromium。

## 自動驗證

執行 `node --test --test-isolation=none`，7 組測試通過：

1. SQLite 停止重啟後，來源、專案關係及附件位元組保留。
2. 遺失來源參照、缺定位與過期 revision 被拒絕。
3. APA 期刊／書籍格式、同作者同年份 a/b、直接引用頁碼、AI 對話排除。
4. 完整 ZIP 還原保持 ID、所有資料與原始附件；重複略過，版本衝突／附件竄改不部分寫入。
5. Markdown 引用、來源定位、人工核對狀態與關係理由；HTML 輸入逸出及 CSV 公式處理。
6. 真實結構的合成 PDF／DOCX 解析，以及無效二進位檔案拒絕。
7. HTTP Host／Origin／token／附件 cookie 邊界、重複匯入及模擬 Gemini 請求範圍。

程式語法檢查：`node --check server.mjs`、`node --check public/app.js`。

## 人工瀏覽器驗證

- 開啟空資料庫，確認首次使用的收件匣及來源匯入指引。
- 建立合成示範專案，確認來源、摘錄、術語、關係與筆記資料出現。
- 開啟來源閱讀器，查看原文、釋義、來源定位與相關概念。
- 新增摘錄、釋義與人工核對狀態；儲存後側欄與筆數更新。
- 開啟寫作工作區，插入含頁碼的引用並儲存。
- 確認 APA 清單、全文搜尋、文獻關係圖與輸出頁。
- 透過瀏覽器檔案選擇器匯入文字與 PNG，確認原圖成功載入。
- 實際下載單篇 Markdown，確認引用標記轉成 APA 文內引用且包含來源清單。

畫面截圖保存在 `docs/screenshots/`；只含合成示範資料。

## 驗證限制

- 未使用真實 Gemini 金鑰，真實雲端連線與帳號配額未驗證；API 邊界以模擬 HTTP 回應測試。
- 沒有 OCR、Word 動態引用欄位、帳號自動同步或大型資料庫效能驗證。
- 沒有在另一台 macOS/Linux 主機上人工操作。GitHub Actions 配置包含 Windows 與 Ubuntu，遠端執行結果須另行查看。
- 響應式 CSS 已提供；尚未在實體手機上人工操作。
