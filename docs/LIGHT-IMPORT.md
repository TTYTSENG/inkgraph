# Light Skills 與墨脈串接

這個功能將 Codex 使用 Light Skills 整理的成果匯入墨脈。墨脈不會自行執行 Light Skills 或自動下載論文。

開啟入口：[Light 成果匯入](http://127.0.0.1:4317/#light)。也可使用原本的墨脈捷徑，再點側欄「Light 成果匯入」。

## 使用方式

1. 開啟墨脈，選擇側欄「Light 成果匯入」。
2. 點「下載格式範例」，把 JSON 檔案交給 Codex。
3. 告訴 Codex：「使用 Light Skills 整理智慧光文獻，依這份 light-inkgraph 格式產生可匯入成果包。只寫可查證資料；來源狀態不明標 UNRESOLVED；沒有讀過全文，不產生原文摘錄。保留來源網址、DOI、研究方法與限制。請將成果存成 JSON 檔案。」
4. 選擇成果檔及所屬專案，按「預覽成果」。預覽不寫入資料。
5. 檢查新增／沿用的資料及查證狀態。不需要的項目按「移除此筆」；確認保留項目後，按「確認匯入這批成果」。
6. 文獻出現在來源文獻庫；摘錄、筆記及關係進入對應區塊。PDF 附件仍需另外加入。

格式範例是合成示例，不是可引用文獻。請先替換成真實研究成果。

## 成果格式

### 第一輪新增約定（2026-10-20）

筆記正文可使用 `[@文獻key]` 或 `[@文獻key, p. 頁碼]`。key 可含中文、底線及句點，不可含空白、逗號或右方括號。匯入時會轉成來源 ID，加入本篇來源清單；輸出 Markdown／HTML 時轉為 APA 文內引用。也接受同專案的既有來源 ID。未知或排除來源的標記保留原樣，在預覽提示，匯出時標示來源遺失。有效引用會轉換，其他筆記文字保持原樣。

來源可另附 `evidence` 物件：`provider`（提供者）、`checkedAt`（提供者查證時間文字）、`url`（證據網址）、`note`（核對紀錄）、`readLevel`（metadata／abstract／fulltext／unknown）。這些都是提供者自陳資訊，墨脈不會因此記為機器或人工核查完成。舊成果包不必增加此欄位。

查證資訊會顯示在預覽與來源閱讀頁，並保留於 JSON、Markdown、HTML 與完整備份。APA、RIS、CSL 等純書目輸出仍維持各自格式，不作查證紀錄的完整備份。

預覽排除清單會存於目前瀏覽器的本機儲存，最多保留最近 30 組檔案內容指紋與專案組合，不保存成果包正文或檔名。切頁、重新整理後，需重新選擇相同檔案內容與同專案再按預覽；不同內容或不同專案不共用選擇。確認匯入成功後清空該組選擇。瀏覽器禁止儲存時仍可匯入，但無法跨頁接續，畫面會提示。

最外層必須有 `format: "light-inkgraph"`、`version: 1`。四個陣列為 `sources`、`annotations`、`notes`、`relations`；可以省略空陣列。每組最多 500 筆，全包最多 5 MB。

| 類型 | 欄位 |
|---|---|
| sources | 唯一 key、title、authors（作者物件陣列）、year、doi、url、summary、method、findings、limitations、verification；可附 journal、publisher、volume、issue、pageRange、tags、cslType |
| annotations | sourceKey、quote（原文）、locator（頁碼／段落），可附 paraphrase、comment |
| notes | title、content、sourceKeys（本包文獻 key 陣列）、tags |
| relations | fromKey、toKey、relation、reason |

作者可以是姓名文字陣列，或使用 `literal`（完整姓名或機構）、`family`／`given` 的作者物件陣列，也可混用。姓名文字會完整保留為 `literal`，只去掉頭尾空白，不猜測姓與名。空白姓名、數字及缺少姓名的物件會被拒絕，並指出文獻位置與作者序號。relation 只接受 `supports`、`contradicts`、`extends`、`compares`。

verification 接受 `CONFIRMED`、`CONFIRMED-MISSING`、`UNAVAILABLE`、`UNRESOLVED`，預設 UNRESOLVED。這是產生者提供的狀態，墨脈不會因為匯入就認定內容正確；摘錄的人工核對欄一律為未核對。

## 重複與資料保護

- DOI 忽略大小寫及 doi.org 前綴；網址忽略片段（# 後的部分）。
- 同專案相同 DOI／網址沿用原資料，不覆寫原有摘要或作者。
- DOI 與網址若對應不同紀錄，停止匯入，請先整理重複資料。
- 文獻已在其他專案時，沿用相同來源 ID，只增加目標專案連結，不移動或覆寫書目及附件。既有多筆 DOI／網址衝突仍需先整理。
- 相同內容的摘錄、筆記、關係也會略過；沒有 DOI／網址的文獻以內容辨識，因此內容改變可能形成新文獻。
- 預覽後若成果包、目標專案、使用的來源／附件或判重結果有變化，必須重新預覽；無關專案的修改不再使預覽失效。
- 匯入採整批交易；任何一筆失敗，整批不寫入。

## 撤回

### 預覽中的移除與復原

文獻、摘錄、筆記及關係都可在預覽按「移除此筆」。這只排除本次匯入，不會刪除資料庫中的既有資料，也不修改原始 JSON。

- 移除文獻時，依附該文獻的摘錄及關係會自動排除。請先復原來源文獻，才能恢復這些相依資料。
- 筆記保留，但會解除被移除文獻的連結，並提示檢查文字引用；筆記文字不會自動改寫。
- 按「復原此筆」可取消該筆手動移除；手動排除的其他項目會繼續保持排除。
- 按「復原全部移除項目」可恢復整份成果包。
- 每次移除或復原都會重新計算新增、重複及移除筆數。更新失敗時無法確認匯入，必須重新預覽。
- 更換檔案或專案會使目前預覽失效。重新選取相同內容的檔案與相同專案後，會恢復已保存的排除清單並重新預覽；檔名可不同，內容必須完全相同。
- 全部移除時不會顯示匯入確認按鈕。

### 匯入完成後撤回批次

按「讀取批次紀錄」，選擇批次後再次確認撤回。只刪除該批新增資料，沿用的原文獻不受影響。

若資料已編輯、部分刪除、加入附件，或有其他資料引用該批成果，會拒絕整批撤回，以免刪掉後續研究。共用來源的新增專案連結也會記入批次；撤回只移除本批新增連結，既有來源保留。該專案後續已有資料使用此連結時會停止撤回。批次記錄可跨重啟使用。

## 安裝後啟用

已在執行的墨脈服務需要重新啟動才會載入新後端。關閉舊服務後，再使用原本捷徑開啟，進入 `#light`。本次功能不改動啟動指令、AI 金鑰或現有資料庫格式。
